# Recovery / Sleep Evidence: Native read contract (proposal v0)

**Status:** PROPOSAL from the Native side (Claude, 2026-10-01). Codex owns the Server read-model implementation. This document records what the Native Recovery/Sleep Evidence implementation (branch `claude/sleep-evidence-native-20261001`) decodes, so the Server either matches it or reports an explicit mismatch. Native does not implement any Server behavior.

The executable example of every payload is `ios/PhysiqueOS/Resources/RecoverySleepFixture.json`. It is synthetic and generated by `ios/Scripts/generate_recovery_sleep_fixture.py`. Native decodes it through the same decoder `ProductionNativeAPI.readResource` uses: camelCase keys, tolerant of snake_case.

## Transport
All four resources are ordinary native reads:
- `GET /api/v1/native/read/<resource>`
- the standard envelope `{contractVersion, resource, authority, generatedAt, data}`
- owner-scoped
- add each one to `nativeProductionContractManifest` reads

A missing resource (404) is shown by Native as a calm "not available yet" state. The Evidence Hub Recovery row stays "Coming soon" and the hub never fails because of Sleep.

| Resource | Query | Bound | Native cache |
|---|---|---|---|
| `recovery-sleep` | none | 14 sleep days | cache-first (90 s default TTL); also feeds the Evidence Hub row |
| `recovery-sleep-trends` | `range=2w\|1m\|3m\|6m\|1y\|all` | `6m`/`1y`/`all` may be weekly-aggregated | cache-first |
| `recovery-sleep-nights` | `limit` (1–60, default 30), `cursor` (opaque) | one page | cache-first |
| `recovery-sleep-night` | `sleepDay=YYYY-MM-DD` | one night | always live (`reload`) |

For an unknown sleep day, `recovery-sleep-night` returns 404 with problem `code: "SLEEP_NIGHT_NOT_FOUND"`. Any other 404 means "not available".

## Enumerations (snake_case values; unknown values decode to `unknown`)
- **Night `status`:** `asleep_recorded`, `in_bed_only`, `no_sleep_recorded`, `awaiting_device`.
- **Detail `status`** (stages / continuity / timeline):
  - `available` (sleep-canon-v2 values)
  - `pending_correction` (v1-computed; the Server must send `null` numbers)
  - `absent` (no stage detail from the counted source)
- **`timeZoneBasis`:** `sample_metadata`, `device_at_ingest`.
- **`timeZoneCertainty`:**
  - `recorded`: from sample metadata
  - `inferred`: phone zone at a near-time sync
  - `uncertain`: zone guessed long after the night, e.g. a historical import. Clock times may be wrong during travel.
- **`origin`:** `prospective`, `historical_import`.
- **Source families:** `oura`, `apple_watch`, `apple_iphone`, `apple_other`, `sleep_cycle`, `whoop`, `autosleep`, `third_party_other`, `manual`. These are family labels only; never send bundle identifiers or device names.
- **Timeline `stage`:** `awake`, `asleep_rem`, `asleep_core`, `asleep_deep`, `asleep_unspecified`.

## NightSummary (shared)
`sleepDay`, `status`, `asleepSeconds?`, `totalAsleepIncludingSecondarySeconds?`, `secondaryEpisodeCount`, `start?`, `end?` (ISO instants of the main asleep extent), `timeZone?` (IANA), `timeZoneBasis`, `timeZoneCertainty`, **`includedInConsistency`**, `windowOpen`, `windowClosesAt?`, `stageStatus`, `primarySourceFamily?`, `origin`.

`includedInConsistency` is the Server's decision. Native never recomputes it. When it is false:
- Native fades the night in the sleep-window chart;
- prefixes its clock times with "≈";
- marks the row "Clock times uncertain".

Total sleep is always shown as exact.

## `recovery-sleep` (landing)
`state` (`available` | `no_data`), `lastNight?`, `nights[14]` (newest first; days without data are explicit entries), `sevenNightAverage`, `priorSevenNightAverage` (`{asleepSeconds?, nightCount, windowNights, minimumNights}`), `trailingAverages[{sleepDay, asleepSeconds?}]` (one per night, Server-derived), `sleepWindow`, `sources[{family, role: preferred|recording|not_recorded, nightsRecorded, windowNights}]`, `evidenceStartSleepDay?`.

`sleepWindow`: `{typicalStartMinutes?, typicalEndMinutes?, startSpreadMinutes?, endSpreadMinutes?, nightsIncluded, nightsExcludedUncertainTime}`.
- Minutes are counted after 18:00 local on the evening before the wake date.
- Typical = median.
- Spread = median absolute deviation.
- Only nights with `includedInConsistency` count.

## `recovery-sleep-trends`
`range`, `granularity` (`night` | `week`), `averageAsleepSeconds?`, `nightsWithData`, `totalSleep[{periodStart, asleepSeconds?, nightCount, trailingAverageSeconds?}]` (newest first).

For `night` granularity, it also carries:
- `sleepWindow`
- `windowRows[{sleepDay, startMinutes, endMinutes, timeZoneCertainty, includedInConsistency}]`
- `continuity[{sleepDay, status, awakeInWindowSeconds?, longestAsleepStretchSeconds?}]`
- `stageMix[{sleepDay, status, deepSeconds?, coreSeconds?, remSeconds?}]`

For `week` granularity those four are `null`.

## `recovery-sleep-nights`
`{items: [NightSummary], nextCursor?}`, newest first.

## `recovery-sleep-night`
`{night: NightSummary, main?, secondary[], provenance?}`
- `main`: `{start, end, inBedStart?, inBedEnd?, inBedSeconds?, stages{status, deepSeconds?, coreSeconds?, remSeconds?, unspecifiedSeconds?, awakeSeconds?}, continuity{status, awakeInWindowSeconds?, longestAsleepStretchSeconds?}, timeline{status, segments[{stage, start, end}]}}`.
  - `inBedSeconds` is non-null only when defensible.
  - Pending-correction nights send an empty `segments` array.
- `secondary`: `[{start, end, asleepSeconds, sourceFamily}]`.
- `provenance`: `{primarySourceFamily, preferenceApplied, reason (sleep-canon reason code), corroborating[{sourceFamily, usable}], algorithmVersion, lastRecomputedAt?}`.

`awakeInWindowSeconds` = canonical main-episode `awakeSeconds`. `longestAsleepStretchSeconds` = the longest run of consecutive asleep segments; an awake segment or a gap breaks the run. Both are descriptive only.

## Explicit non-fields
There is no score, target, threshold, good/bad label, readiness, efficiency, latency or awakening count anywhere in this contract.

Being shown in Evidence does not change `strategicEvidenceEligibility`. Historical-import nights stay permanently Evidence-only.
