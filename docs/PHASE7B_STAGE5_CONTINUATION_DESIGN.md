# WP2B Stage 5 provenance-preserving continuation

Status: local implementation for Founder review. Not live binding or execution authority.
Stage 3 and Stage 4 remain closed PASS. No rerun or rewriting of their evidence is required.

## Ownership and authority

`PHASE7B_WP2B_STAGE5_CONTINUATION_BINDING`, schema 1, is an immutable non-executable binding, not a replacement capture authorization. It has `executionAuthorized=false`, `founderExecutionAuthorizationRequired=true`, `stage5Only=true`, `automaticRetryAllowed=false`, and `wp2cAuthorized=false`.

The original, hash-selected capture authorization remains the sole authorization consumed, via its existing marker. There is no second authorization or second consumption marker. A fresh explicit Founder Stage-5 GO is required separately. The launcher also requires the acknowledgement `WP2B_STAGE5_FINALIZE_ACCEPTED_CAPTURE_LINEAGE_EXACTLY_ONCE`; an acknowledgement is an operator attestation, not a cryptographic Founder signature.

The binding contains:

- `capture`: original tooling commit; invocation hash; authorized Stage 3 and Stage 4 launcher hashes/bytes from that invocation; original authorization ID/hash/path hash/issue/expiry; pending descriptor hash; ciphertext and plaintext/decrypted stream hashes/bytes; native recipient and age identities; source inventory and plan; quiescence hash and original quiescence tooling lineage.
- `finalization`: current tooling commit and machine-derived hashes/bytes for the entire enumerated Stage-5 source/module dependency set, including the current Stage 5 launcher.
- `receipt`: exact existing receipt nonce, canonical file SHA-256, filename and bytes. Receipt validation also proves its packet and retained-laptop identity/teardown bindings.

Stage 4's launcher identity records the authorized capture-invocation artifact. It is not claimed to be a signature generated by the receipt; the receipt remains governed by the accepted Founder Stage-4 result and out-of-band hash pin.

`phase7bNewWorkPackage2Stage5ContinuationBinding.ps1` is the future create-new generator. It requires a clean published branch/parity, exact hash-selected original evidence, verified receipt transport copy and explicit preparation-only acknowledgement. It computes identities rather than transcribing chat hashes into source. It writes only one ignored binding under the repository `.tmp`; it does not modify or consume an authorization.

Implementing this mechanism changes source identities. The implementation's eventual published commit, not its base commit, must become `finalization.toolingCommit`. No live binding may be generated while this local patch is under review. Normal invocation-contract generation is not used to replace the historical capture contract.

## Read-only gates and mutation order

The continuation launcher keeps the original invocation and authorization inputs. It validates current repository identity, current source hashes and explicit GO independently from capture lineage. The existing exact-44-property pending compatibility validator is unchanged.

Before the first durable Stage-5 write, it re-derives the full binding from exact original evidence, verifies the local ciphertext and canonical receipt transport bytes, validates original authorization expiry/unused state, and rejects any extra attempt-root object beyond packet and pending descriptor. Contradictory/partial/unknown binding fields fail canonical equality. A preexisting final descriptor, imported receipt, teardown or marker is not a normal continuation state. There is no automatic recovery or retry.

Durable ordering remains primary teardown evidence, canonical receipt import, final descriptor, original authorization marker. The finalizer repeats the complete continuation validation against the imported receipt. Authorization expiry is rechecked immediately before marker creation. If it expires after descriptor persistence but before consumption, finalization fails with residue preserved for review; the marker is not created.

Expiry is never extended. If the original authorization expires before closure, this continuation is not executable. A new explicit Founder recovery-policy decision is required; a replacement capture authorization or Stage 3 rerun is not an automatic remedy.

## Portable final descriptor

Descriptor schema 1 retains all existing capture-owned fields unchanged. An additive, versioned `stage5Provenance` object embeds the complete canonical binding plus its SHA-256, exact Founder acknowledgement and finalization timestamp. `captureAuthorizationToolingCommit` and `invocationContractSha256` retain their original meanings. Current finalization tooling is recorded separately inside the extension.

Both `phase7bBuildWorkPackage2RestoreIso.ps1` and `phase7bIsolatedGuestRestoreInterface.ps1` validate the extension when present, including its canonical hash, exact nested shapes, capture-field equality, receipt hash, artifact set, and closure time within original authorization lifetime. Existing descriptors without this extension remain supported through their existing hash/packet/round-trip gates. Partial or contradictory extensions fail closed. Restore does NOT require access to the old primary host or a still-unexpired capture authorization months later. Separate WP2-C authorization remains mandatory.

The media builder preserves the entire extension when adding separate guest authorization. The completed-capture resume script reads only pending descriptors, whose shape is unchanged. Report reconciliation and evidence-timeline code consume stage reports rather than this descriptor's provenance object. Their report schemas remain unchanged; migration-safety and reconciliation suites cover those contracts. No consumer may interpret the capture commit as the finalization commit.

## Nonsecret receipt return preparation

Prepared standalone helper: `scripts/phase7bWorkPackage2ReceiptReturn.ps1`. It is not run during development. Later, hash-deliver this single source-owned script to the laptop through the already-reviewed bounded primary-to-laptop tooling-delivery pattern. No migration module bundle is required on the laptop.

On the laptop, `InspectLaptop` performs only local receipt discovery/read and emits a compact nonce/hash/size pin. `ServeLaptop` validates exactly one receipt matching the attempt beside the banked packet, rejects unknown/nonreceipt fields, holds only receipt bytes, and serves one exact filename on `192.168.1.68:49182`. It never reads the packet or changes the receipt/share/receiver. A unique temporary inbound firewall rule allows only `192.168.1.69`, TCP/49182, the laptop's local address, actual Public/Private profile, and current PowerShell executable. Profile Any is prohibited.

The laptop shows one compact nonsecret JSON pin (nonce, SHA-256, bytes). The Founder copies this small pin, not the Base64 receipt, to `ReceivePrimary`. The Primary uses a fixed laptop IP, no proxy, no redirects, bounded reads and no credentials. It verifies exact response bytes/hash/nonce and writes a create-new transport copy in a separately prepared ignored `.tmp` location. This copy is NOT canonical Stage-5 receipt import. `Read-Phase7BStage5ReceiptTransport` performs the full authoritative receipt and canonicalization checks before binding or execution. The importer gains a file-input option with the same hash/receipt/canonicalization gates; no manual Base64 transcription is needed.

The server stops after one request or 300 seconds; request parsing is capped at 8 KiB/5 seconds. Finally stops the listener and removes/verifies removal of only its uniquely named temporary firewall rule. As with the previously reviewed pattern, process termination/power loss cannot guarantee execution of finally; such interruption is a residue-bearing hard stop requiring read-only reconciliation, not blind retry. No persistent service or Stage-2 SMB infrastructure is created.

Exact receipt nonce/hash/bytes are deliberately NOT invented here: they must come from the durable laptop file during a separately authorized inspection/return attempt. The original receipt remains immutable. No live laptop access occurred during preparation.
