# V3 plumbing proposal — Founder review, not canonical documentation

Status: isolated server playground only. No production server, Native or Web integration, deployment, production writes, published-artifact rewrites or canonical-documentation changes. September DEXA/Weekly/Home calibration remains 79%. Passing synthetic fixtures does not grant production acceptance.

## Meaning and language ownership

Narrative V3 is the deterministic server-owned realization layer for derived meaning wherever language is required, not merely a briefing writer. It does not ingest evidence, run an LLM, own every button/field or replace all domain presentation. Strategic Interpretation owns Goal-relative judgments; Confidence owns the forward-looking completion outlook; Coaching State owns longitudinal questions and decision transitions. Narrative realizes their approved meanings and configured vocabulary. Surface projections select emphasis, never reevaluate evidence.

| Content boundary | Owner | V3 role |
|---|---|---|
| A: canonical facts, values, dates, schedules, counts | typed canonical read/presentation contracts | none merely to display a fact |
| B: neutral navigation, editors, validation/help, labels | ordinary static product UI | none; dynamic generated UI copy is not intended |
| C: non-Goal domain classification, source reconciliation, comparability, performance calculation | approved deterministic server domain presentation adapter | may supply capabilities; no forced Strategic Interpretation |
| D: Goal-relative judgment, recommendation, outlook, practical meaning | canonical V3 strategic/confidence/coaching state, deterministic Narrative projection | required; clients do not invent interpretation |
| E: backend terms in user-facing text/a11y | display-safe presentation contract | translate/remove at the applicable domain or strategic boundary |
| F: specialized rework | separately approved project | dependencies explicitly preserved, not silently accepted |

Numeric PR facts are A; comparable exercise performance classifications can be C; whether they support this Goal is D. Numeric intake versus configured target can be C; whether intake strengthens Goal confidence is D. An empty history prompt is B/C; why missing evidence matters to this Goal now is D. Draft plan readiness is C, not proof of strategy effectiveness. Factual scheduled next DEXA date is A; its strategic purpose is D.

## Goal-generic foundation

All core objective/achievement, guardrail aggregation, evidence authority, feasibility, persistence, uncertainty, question lifecycle, recommendation, takeaway, affect and confidence reducers use structured semantics, not Goal/source/metric-name branches. Goal Contract supplies objectives and desired direction OR stable/range success, independent success criteria, significant-change thresholds, optional forecasts/deadlines/durations, phase/revision identity, exposure, authority/quality policies, zero-to-many independent guardrails/consequences, question predicates/priorities, evidence alternatives and cadence, action prerequisites and vocabulary.

Evidence adapters normalize observations and declare capability/quality/directness/comparability. They do not declare universal strategic supremacy. Performance-only and future custom metrics use the same contract/authority path. `custom_declarative` is a versioned whitelisted predicate, not executable code or a Goal-specific handler. No specialized handler was needed for these 18 cases. Any future unavoidable extension needs an explicit version, same structured I/O, deterministic tests and Founder-visible justification outside the core reducers.

Maintenance in range can already be achieved without directional movement; configured duration Goals remain in progress until duration criteria are met. Objective-policy satisfaction and terminal Goal success are distinct: the custom fixture satisfies an intermediate policy while its target remains unfinished. Multi-objective achievement combines configured required criteria, not a preferred Founder metric.

Question lifecycle now evaluates successors on subsequent evidence, preserves historical answers across revisions/contradictions, supersedes invalid open revision scopes and supports configured conditional/prioritized safety questions. A missing new window does not demote demonstrated feasibility/persistence. Execution deterioration can lower future Goal confidence without erasing historical strategy findings.

Evidence request timing plus vocabulary drives names and natural horizons; unknown/multiple alternatives retain generic next-check wording. Risks bind actual configured range/threshold and human labels or lexical risk phrases, not backend guardrail enums. Strategic decisions cannot be hidden in vocabulary strings.

## Source findings requiring migration

Home active-chapter and Active Goal preview contain `build_lean_mass` paths and Founder-phase reasoning. Legacy Goal and Photo Event screens contain fixed cut/preservation/transition interpretations. Training progression has phase-specific expectations. Existing V2 cadence/Event/domain evaluators are mostly server-owned but do not yet share V3 canonical judgment. None was modified in this audit. Source ownership alone is insufficient: independently server-composed stories still need canonical meaning parity.

All eight Operating Plan domains were reviewed: server read sections primarily supply factual configuration/status, while strategy-detail purposes and legacy StrategyDomain/OperatingPlan copy include derived reasons. Recovery is not assessed in the real fixture; actions may not advise preserving it merely from an overall positive strategy finding. Peptide/supplement integration does not authorize new clinical claims or dose recommendations.

Priority action scheduling/completion remains existing domain infrastructure. Goal-relative subtitles/why-now/detail rationale migrate; labels such as Foam Rolling and static execution instructions do not.

## Existing runtime generated prose — separate architecture decision

PhotoInterpreterService currently calls vision and its prompt requests coaching/should-change-plan/next-comparison strategic prose, not just observations. Photo reinterpretation/review paths feed those outputs downstream. This is an existing parallel strategic-language source. Proposed migration: preserve vision extraction/comparability, then have eligible observations enter deterministic V3 and stop treating generated strategy prose as canonical. Founder approval is required; no LLM/provider behavior changed here.

Screenshot extraction and speech transcription are existing runtime observation-extraction services, not Narrative V3 dependencies. Keep their provider diagnostics private and domain error/status messages human-readable. Existing NarrativeEngine is deterministic; labs may intentionally expose debug/provider output. V3 introduces no runtime LLM calls.

## Leakage removal gate

Confirmed source sinks include raw phase-edit blocking reason codes, unfiltered exception messages, Weekly/Midweek accessibility enums, and phase-review generic enum humanization in explanatory prose. Potential contract leaks include Native photo status/provenance, interpreter warnings/provider failures and training-history implementation wording. Opaque routing IDs, React keys, hidden inputs, private lineage/fingerprints and restricted debug output are not automatically user-facing leaks. Human Connected/Suggested source labels were checked rather than falsely counted as raw enum leakage; their truthfulness is a separate product concern.

Future contract tests must inspect normal visible copy AND assistive labels, reject internal IDs/provider/storage keys/reason codes and first-person system personification, and verify that display-safe domain messages are not routed through strategic reasoning just to translate an error.
