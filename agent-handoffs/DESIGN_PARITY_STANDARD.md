# PhysiqueOS design parity standard

A surface is not at parity merely because every field or data value appears somewhere in a mockup or implementation.

Parity requires preservation of the production surface’s:

- hierarchy;
- ordering;
- prominence;
- grouping;
- relationships;
- navigation;
- disclosures;
- media placement;
- workflow;
- interaction;
- content;
- conditional and asynchronous state behavior.

## Review rule

For every translated surface, audit the current production source and enumerate each section, action, destination, disclosure and materially distinct state before rendering. A coverage matrix must map each production element to a direct artifact or a representative template.

When a disclosure changes the amount or kind of information shown, validate both collapsed and expanded states. When media is central to the workflow, preserve its geometry, placement, roles, tap targets and inspection behavior—not only its metadata.

If a mockup loses production structure while retaining all fields, that is a design-harness parity defect, not automatically a shipping-code defect. Add a shipping delta only when the accepted target genuinely differs from current shipping behavior.
