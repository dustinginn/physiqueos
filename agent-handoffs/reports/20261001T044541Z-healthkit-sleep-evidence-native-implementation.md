## Time-zone handling (Texas travel)
- Native never infers or overrides a zone. It shows the Server's `timeZone`, `timeZoneBasis` and `timeZoneCertainty`.
- **Uncertain historical nights:** shown with the zone abbreviation, a note ("Total sleep is exact. The clock times use a time zone inferred after this night and may be off if you were travelling."), and "uncertain" in Source & Data.
- **Server-excluded nights** (`includedInConsistency == false`): "≈" clock times, a "Clock times uncertain" tag and row marker, faded window bars, and excluded from typical-window statistics with an explanatory line.
- Total sleep is always exact.
- The fixture models historical nights as `uncertain` and Sep 26–29 as Server-excluded. Which real nights the Server excludes is Codex's decision; no travel inference from unrelated data.

## v2 gating
- Stage minutes, Awake, continuity and the stage timeline render only for `status == available`.
- `pending_correction` shows "Stage detail is being recalculated." with no numbers.
- `absent` shows "Stage detail is not available from this source".
- Unknown future enum values decode as `unknown` and render the non-numeric state.

## Performance
- **Landing:** exactly one bounded read (`recovery-sleep`, 14 nights, cache-first). The hub's fail-soft Recovery read is the same cached resource, so opening Recovery right after the hub costs no extra request.
- **Trends:** one ranged read per selected range; weekly aggregation for long ranges is Server-side.
- **Night:** one scoped live read.
- **History:** paged; no all-history load anywhere.
- Pull-to-refresh invalidates only the `recovery-sleep*` resources.
- The hub keeps its existing parallel-read structure; Sleep cannot fail it. That is compatible with Codex's later fail-soft hub performance work.
