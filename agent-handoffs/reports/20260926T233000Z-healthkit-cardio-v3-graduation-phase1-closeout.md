## What was built

Extended the existing, already-live HealthKit graduation policy architecture (`src/domain/services/HealthKitGraduation.js`, `src/platform/database/HealthKitGraduationReader.js` — the same mechanism already governing Activity/Nutrition canonical-day graduation) with a new `cardio_training` domain, scoped to discrete canonical HealthKit **Cardio workouts** (walks/runs/rides) only. Strength is explicitly excluded and keeps its own separate Logger-confirm reconciliation workflow regardless of this scope's state.

Key design decision: this is **not** folded into the existing day-based `overlay()`/`assessHealthKitGraduation()` machinery, which models a "partial day vs. complete day" state for the Briefing Evidence Settlement gate. A canonical HealthKit workout has no such partial state — it is a bounded, already-finished event the moment it's canonicalized — so it needs no settlement-gate participation. Instead, a new parallel function `overlayGraduatedHealthKitCardioWorkouts` was added to the same file, wired into the reader as a new `overlayCardioWorkouts` method, and chained **after** the existing day-overlay in `src/application/composition/providerBriefingCadenceComposition.js`'s evidence-runtime construction — the exact point V3 Confidence/Narrative generation consumes evidence.

The new overlay reuses the existing, already-reviewed, already-live `projectPresentedHealthKitCardioTrainingRecords` (from `HealthKitCardioTrainingPresentation.js`, the same projector Training Day/History already use) for shape, per-day grouping, and duplicate suppression against existing Founder-logged (screenshot/Logger) Training evidence — it does not re-derive any of that; it only adds the evidence-eligibility scope check and strategic-eligibility stamp on top.

**Ships inert.** The live production graduation policy record's `evidenceEligibility.domains` is `["activity","nutrition"]` and is completely untouched by this change — `cardio_training` only becomes reachable once a separate, explicitly Founder-authorized policy update adds it via the existing `healthKitGraduationPolicy` ops tool. Deploying this candidate changes no runtime behavior by itself.
