# Reusable implementation method

1. Pin implementation, Server contract, and locked-design commits independently.
2. Audit route identity, data projection, mutations, terminal states, reconciliation, and shared components before styling.
3. Gate the pilot by canonical identity—not display copy—and leave every non-pilot route unchanged.
4. Translate exact locked geometry and semantic tokens into a local surface implementation before proposing shared-system extraction.
5. Use a DEBUG-only, source-shaped launch fixture for deterministic real-screen captures. Keep Release on production loading and theme authority.
6. Assert canonical copy, action geometry, navigation structure, and safety behavior in UI tests; assert identity/state/route mapping in unit tests.
7. Capture unmodified `XCUIScreen` Dark and Mineral Light images at the locked point geometry, compare to the exact accepted references, and correct every product-surface mismatch.
8. Run the focused tests and a Release compile, publish implementation and artifacts as separate commits, and stop for review before scaling.

For a later family rollout, first obtain Founder acceptance of this pilot. Then decide which local typography/palette/layout pieces become shared Priority Detail components; do not generalize them from this pilot pre-emptively.
